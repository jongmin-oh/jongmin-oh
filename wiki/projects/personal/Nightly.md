# Nightly — 한 캐릭터에 집중한 페르소나 대화 에이전트

**성격**: 1인 개발 · 별도 저장소 · 진행 중  
**기간**: 2026.08.09 – 현재

## 어떤 서비스인가

메신저로 **하나의 캐릭터**와 대화하는 봇.
[[projects/company/캐릭터챗봇API]]를 운영하며 하고 싶었지만 **레플리에서는 구현하지 못했던 계획들을 실제로 만들어보는 프로젝트**다. 회사 서비스가 감당해야 하는 제약(다수 캐릭터·대규모 트래픽·기존 구조) 밖에서, 제품 가설을 끝까지 밀어붙이는 실험대.

## 왜 하나의 캐릭터인가

**과금 유저 관찰에서 나온 가설.**
대부분의 과금 유저는 여러 캐릭터를 옮겨 다니는 것보다 **한 캐릭터와 오래 쌓은 애착 관계**를 더 중요하게 여겼다.

그렇다면 카탈로그를 넓히는 대신 **하나를 깊게** 파는 쪽이 맞다. 캐릭터를 하나로 좁히면 그 캐릭터에 대해서만 온톨로지를 구축하고, 관계·기억·맥락을 훨씬 촘촘하게 설계할 수 있다 : 다수 캐릭터를 지탱해야 하는 구조에서는 비용상 불가능한 깊이다.

> 기술 선택이 아니라 **과금 유저의 행동에서 출발한 제품 결정**이고, 그 결정이 아키텍처(온톨로지·GraphRAG)를 규정했다.

## 어떻게 일했나

**모델 드리븐 구조로 설계했다.**  
LangGraph 위에 여러 도구를 붙이고 **ReAct 구조**로 묶어, 흐름을 코드로 하드코딩하지 않고 **모델이 판단해 도구를 고르고 필요한 만큼 캐게** 했다. 무엇을 얼마나 조회할지를 규칙으로 못 박는 대신 모델에게 넘긴 설계.

**캐릭터 온톨로지 + GraphRAG로 깊이를 만들었다.**  
캐릭터의 인물·관계·사건·장소를 위키 문서로 쓰고 이를 지식 그래프로 적재해, 대화 중 필요한 조각만 검색해 끌어온다. 캐릭터를 문장 몇 줄의 설정이 아니라 **구조화된 지식**으로 다룬 것.

**검색을 페르소나 모델에서 떼어냈다.**  
검색은 별도의 빠른 모델이 맡고 페르소나 모델은 결과만 받는다 — 도구 호출 흔적이 말투를 흐리는 것, 고정부가 앞에 남아야 프롬프트 캐시가 유지되는 것, 메신저 대화라 왕복 지연이 체감된다는 것 때문.

**할루시네이션을 "더 정확히 찾기"가 아니라 "근거를 넉넉히 주기"로 뒤집어 풀었다.**  
근거가 얇으면 모델이 빈칸을 지어낸다. 검색 정확도를 올리는 대신 최소 사실 개수 하한을 두고 모자라면 이웃 사실로 채우게 했다. 검색 단위도 통짜 문서에서 낱개 사실로 쪼갰다.

**정규화를 일부러 하지 않았다.**  
상대에 대해 아는 것을 필드로 모으면서 값을 enum으로 정규화하지 않고 문자열로 뒀다. `"3교대, 나이트 주엔 낮에 잠"`이 `{shift_work: true}`보다 프롬프트에서 낫고 매핑 로직도 안 붙는다. ([[skills/working-style]] 오버엔지니어링 경계)

**서버리스에서만 생기는 문제를 직접 해결했다.**  
호출마다 죽는 환경의 턴 카운트, 관측 데이터 유실, 메신저 재전송, 정렬 가능한 ID — 프레임워크 튜토리얼에는 안 나오는 문제들. 지식 그래프는 빌드 때 **모든 주제가 허브에서 도달 가능한지**까지 스스로 검증하게 했다(도달 못 하면 검색이 영원히 못 닿는 섬이 된다).

## 스택

`Python` · `LangGraph / LangChain` · `ReAct` · `Neo4j (온톨로지 · GraphRAG)` · `Langfuse` · `AWS Lambda (SAM)` · `DynamoDB` · `OpenRouter`

## 의의

- **회사에서 못 한 계획의 실행판.** 운영 중인 서비스의 제약 때문에 미뤄둔 가설을 개인 프로젝트에서 끝까지 구현해본다 — 아이디어를 묵히지 않고 배포까지 미는 방식.
- **제품 결정이 아키텍처를 규정한 사례.** "과금 유저는 한 캐릭터와의 애착을 중시한다" → 하나에 집중 → 온톨로지·GraphRAG로 깊이 확보. 기술에서 출발하지 않는 [[overview|문제중심 정체성]]의 최신 사례.
- [[projects/company/장기기억시스템]]에서 내린 판단(RAG 폐기 → 구조화된 기억)의 **반대편 실험**. 거기서는 검색 계층을 걷어냈고, 여기서는 넣되 사실 단위 + 에이전트 선별로 다시 설계했다.
- [[skills/technical]]의 공백이던 **에이전트·지식 그래프**를 실제 배포되는 코드로 메웠다.
