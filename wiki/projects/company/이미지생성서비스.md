# 캐릭터 이미지 생성 서비스 0→1 구축

**소속**: [[entities/companies/레플리\|Reppley]]  
**특이사항**: 이미지 생성은 사전 경험 없는 영역 — 완전한 0→1

## 문제

- 레플리 사용자가 캐릭터 이미지 만들려고 **외부 서비스로 이탈**
- 외부 서비스: 조작 어렵고 대부분 해외 서비스 → 연령대 낮은 주 타겟층 진입장벽 높음
- SaaS API: MAU 3만 규모에서 호출 단가가 운영 압박

**결정**: "앱 내 무료 + 빠른 생성"을 제품 차별점으로 → 직접 구축.

## 주요 기능

- 웹툰 / 퇴폐 / 감성 / 스케치 스타일 이미지 생성

## 핵심 결정 3가지

### 1. 인프라 — SaaS 대신 GPU 직접 계약

가비아 RTX A5000 시간당 단가 계약.
호출당 단가 → 시간당 단가로 전환 → **트래픽이 늘수록 단위 비용 하락**.

단, 이건 클라우드가 아니다. **GPU 하드웨어 대여 + 네트워크 서비스** — 물리 장비를 벤더가 들고 있는 구조이며, 이 성격이 뒤에 장애로 되돌아온다.

### 2. 속도 — 서빙 엔진 자체 구현

| 도구 | 장점 | 한계 |
|------|------|------|
| ComfyUI | 빠른 추론 | REST API 없음 |
| SD WebUI | /sdapi/v1 API | 무겁고 느림 |

→ 두 트레이드오프를 동시 해결: ComfyUI 실행 엔진 위에 SD WebUI 호환 REST API를 얹은 헤드리스 서버 직접 구현.  
→ [[projects/personal/ComfyUI-API-서버\|ComfyUI API Server]] (GitHub 공개)

### 3. 비용 — 번역 캐싱

한→영 번역 키워드 캐싱 시스템. 최초 1회만 번역, 이후 캐시 히트로 번역 API 비용 선형 증가 차단.

### 4. 운영 리스크 — NSFW 자동 감지

NSFW 감지 모델 자체 개발 → 부적절 이미지 자동 차단. ([[projects/company/운영도구내재화\|운영 도구 내재화]]의 이미지 자동 검열과 연계)

## 스택

`Python` · `FastAPI` · `ComfyUI` · `Stable Diffusion` · `가비아 GPU (RTX A5000)` · `Docker Hub` · 대체 GPU: `AWS EC2 g6` / `RunPod A40`

## 장애 경험 — 2회, 둘 다 GPU 미인식

직접 계약의 이면. 두 번 모두 **하드웨어가 GPU를 인식하지 못하는** 장애였고, 물리 장비는 우리가 고칠 수 없다.

| | 원인 | 임시 대응 | 근본 조치 |
|---|---|---|---|
| 1차 | 드라이버 자동 업데이트 → 버전 불일치 | AWS EC2 g6 기동 + 라우팅 전환 | 드라이버 버전 고정, 자동 업데이트 off |
| 2차 | 실제 장비 결함 | RunPod A40 ($0.5/h) 기동 | 벤더 장비 회수·수리 |

**2차의 진짜 문제는 GPU가 아니라 시간이었다.** 벤더가 장비를 챙겨 수리하는 데 시간이 걸리고 주말은 운영하지 않는데, **우리 서비스 피크는 주말**. 결함 자체보다 *복구 시점을 우리가 통제할 수 없다는 것*이 컸다.

**RunPod를 택한 이유**: 1차에서 띄운 AWS 인스턴스 단가가 너무 비쌌다. A40 시간당 $0.5면 충분 → 수리 완료까지 유지.

**대응을 런북으로 고정**: 서비스 컨테이너 이미지를 Docker Hub에 상시 보관 → 재발 시 docker 명령만으로 즉시 기동. 1차는 즉흥 대응, 2차는 대응 + 재발 대비까지.

### 여기서 남은 것

- **저렴한 인프라 단가에는 복구 시간이 포함되어 있지 않다.** 시간당 단가 5배 절감의 대가는 장애 시 벤더 일정에 종속되는 것 (→ [[reflections/비용을-줄이는-사람]] 그림자).
- 해답은 계약을 바꾸는 게 아니라 **핫스왑 경로를 상비하는 것**. 같은 컨테이너가 다른 GPU 공급자(AWS·RunPod)에서 즉시 뜨면, 싼 계약을 유지하면서 리스크만 상쇄할 수 있다. 서빙 엔진을 직접 만들어 컨테이너로 포장해둔 것([[projects/personal/ComfyUI-API-서버\|ComfyUI API Server]])이 공급자 교체를 가능하게 했다 — 의도한 효과는 아니었지만 결과적으로 자체 구현의 두 번째 이득.

*[미기록] 두 장애의 발생 시점, 각 다운타임 길이.*
